👨‍💻 Code-Together Activity 17: Graph Representations & Traversals

🎯 Overview

An in-class code-together activity implementing an undirected graph using an adjacency list (unordered_map<string, vector<string>>). Students implement Graph.cpp guided by the instructor, building add_vertex, add_edge, query methods (has_vertex, has_edge, vertex_count, edge_count, neighbors), and two traversal algorithms: BFS (breadth-first search using a queue) and DFS (depth-first search using a stack). The activity builds a social network graph and demonstrates how BFS visits level-by-level while DFS dives deep before backtracking.

📖 Learning Objectives

By completing this activity, you will be able to:

  • Implement an adjacency list using unordered_map and explain why it is space-efficient for sparse graphs: O(V + E)
  • Implement add_vertex and add_edge for an undirected graph, understanding that each edge is stored in both directions
  • Implement has_vertex, has_edge, vertex_count, edge_count, and neighbors using the find() / end() pattern on unordered_map
  • Implement BFS using a queue and visited set, and explain why it finds shortest paths in unweighted graphs
  • Implement DFS using a stack and visited set, and explain why neighbors are pushed in reverse order
  • Compare BFS vs DFS: when to use each, how the data structure (queue vs stack) determines visit order, and why both are O(V + E)

📚 Teaching Order

Work through the files in the order main.cpp calls them:

1. Graph.h — Class declaration and data member

Section What You’ll Learn
Adjacency list declaration Why unordered_map<string, vector<string>> — O(1) vertex lookup, O(V+E) space
Graph vs Tree Graphs can have cycles, multiple paths, and vertices with any number of connections
Adjacency list vs matrix List: O(V+E) space, fast neighbor iteration. Matrix: O(V²) space, O(1) edge lookup

2. Graph.cpp — Implementations (9 TODOs + print provided)

Section What You’ll Learn
Section 1: Constructor Empty graph — the unordered_map starts empty, no initialization needed
Section 2: add_vertex Idempotent insertion using find() / end() pattern; safe to call multiple times
Section 2: add_edge Undirected = two push_back calls (forward + reverse link); auto-creates vertices
Section 3: has_vertex O(1) hash table lookup — find() != end()
Section 3: has_edge Two-step lookup: find vertex in map, then linear search neighbor list with std::find
Section 3: vertex_count / edge_count Map size for vertices; sum all neighbor sizes and divide by 2 for edges (structured bindings)
Section 3: neighbors Find vertex, return it->second (the neighbor vector); return empty if not found
Section 4: BFS Queue (FIFO) + visited set; mark visited at enqueue time; level-by-level = shortest path
Section 5: DFS Stack (LIFO) + visited set; check visited at pop time; push in reverse order (rbegin/rend)
Section 6: print (provided) Structured bindings, nested loop with comma separation, hash order is non-deterministic

3. main.cpp — Demo driver (4 sections)

Section What You’ll Learn
Section 1: Build a Graph Build social network with 5 vertices and 5 edges; verify counts and print adjacency list
Section 2: Queries Test has_vertex, has_edge, neighbors on the social network graph
Section 3: BFS BFS from Alice — observe level-by-level visit order
Section 4: DFS DFS from Alice — observe depth-first dive, compare order with BFS

🔧 Troubleshooting

CMake does not configure automatically

  1. Make sure you have Desktop development with C++ workload installed in Visual Studio
  2. Go to Project → CMake Settings and ensure the configuration is correct
  3. Try Project → Delete Cache and Reconfigure
  4. Verify that CMakeLists.txt is in the root of your cloned repository

Tests fail to build

  • Google Test is fetched automatically via CMake’s FetchContent — make sure you have an internet connection during the first build
  • Do not modify header files in the include/ folder

Running the Program

  1. In Visual Studio, select ct17-graph-representations.exe as the startup item from the dropdown
  2. Press Ctrl+F5 to run without debugging
  3. You should see output from each section as you complete the TODOs
Tip: Look for the // ! DISCUSSION: comments in each file — these explain the “why” behind each concept. The // ? SEE DIAGRAM: comments point you to visual aids in the images/ folder. Every function in Graph.cpp has a matching SVG diagram with a code walkthrough.
